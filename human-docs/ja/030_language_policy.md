# 言語ポリシー（AI正本 docs / 人間向けは human-docs）

このリポジトリでは、AI が読む正本と、人間向けの言語ツリーを分けて扱います。

- AI の正本: `docs/` `knowledge/` `agent/`（XID 管理対象）
- 日本語の人間向け: `human-docs/ja/`
- 英語の人間向け資料: `human-docs/en/`

## 英日間を XID で相互参照しない理由

XID は、改名・移動・分割・統合があっても参照を安定させるための主キーです。これを安定して運用するには、**XID 管理対象の正本が1つ**であることが重要です。

両言語を同一の XID インデックスで管理すると、次の問題が避けられません。

- 翻訳により **XID が重複**しやすい
- `rewrite/check` の対象が曖昧になる（どの言語へ解決すべきか）
- 運用コストが増える割に得られる効果が小さい（日本語側は主に人間向け）

そのため、次の方針を採用します。

- 管理リンク（`#xid-...`）は **英語側（`docs/` / `agent/`）で完結**させる
- `human-docs/` は **XID インデックスの対象外**とし、`xref rewrite/check` の管理対象にしない

## 英日間の導線が必要な場合

言語間の行き来が必要な場合は、XID 管理リンクではなく、シンプルな“案内リンク”を置きます。

- 正本 docs 側: `- Japanese: ../human-docs/ja/<path>.md`
- 日本語側: `- English canonical: ../../docs/<path>.md`
- 英語 human-docs 側: `- English canonical: ../../docs/<path>.md`

これらは XRefKit の自動書き換え対象ではないため、最小限にし、パスが安定するように運用します。

## この設計における「正本」

- AI が読む・参照する正本は `docs/`（XID 管理対象）
- 人間が検証できる原本は `sources/`
- `human-docs/` は人間向けの言語ツリーで、参照グラフ（XID）とは分離する
