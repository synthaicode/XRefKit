# XRefKit 知識・手順管理シナリオ

この資料は、XRefKit が組織固有知識と AI に任せる手順を、どう管理・実行・改善するかを説明する。組織への配布方法は扱わず、管理済みの正本を作るところまでを範囲とする。

## ゴール

- 視聴者が、責務定義、組織固有知識、実行記録、証拠、元資料を分ける理由を理解する。
- 視聴者が、限定責務を作業進行規約の中で実行し、未完了を完了扱いしない仕組みを理解する。
- 視聴者が、実行時の XID 利用記録を管理対象の改善へ戻す流れを理解する。
- 視聴者が、検証済みで更新可能な正本が組織配布の入力になることを理解する。

## 対象者

- このリポジトリを初めて見る人
- AI を業務へ入れたいが、どう構造化すべきかを知りたい人
- 他の AI や人へ XRefKit を説明しなければならない人

## 構造

1. このリポジトリは何か
2. なぜ文書置き場では足りないか
3. 管理対象をどの層に分けるか
4. Skill 実行をどう囲うか
5. 外部入力で方針が崩れないようにどう守るか
6. 継続作業と複数 AI をどう引き継ぐか
7. 人間はどこで判断するか
8. 更新・検証可能な正本を作る

## 範囲外

- Python パッケージとしての配布
- 世代単位の公開と `current.json`
- リポジトリ、導入済みパッケージ、MCP による参照解決
- クライアント側での整合性・信頼確認

これらは「XRefKit 組織配布」で説明する。
