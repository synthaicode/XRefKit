# XRefKit Slide Authoring Checklist

055、064、065、073で採用している書き方を、新規作成とレビューで判定できる形にまとめる。063を含む既存資料を変更する場合も、特別な理由がなければこの基準へ合わせる。

## 1. 資料の責務

- [ ] 資料全体が答える問いを一つの文で定義している。
- [ ] 隣接資料が答える問いを繰り返していない。
- [ ] Why、How、Boundary、Implementation、Improvement and Distributionのどこを担当するか明示している。
- [ ] 実装されていない製品機能を説明の都合で追加していない。
- [ ] 最終ページが次の資料または次の業務実行へ接続している。

## 2. 一枚の構造

- [ ] 一枚につき中心メッセージは一つである。
- [ ] タイトルだけで、そのページの結論または問いを把握できる。
- [ ] 補足文はタイトルを説明し、別の主張を追加していない。
- [ ] 本文は3項目前後に絞り、長い段落を置いていない。
- [ ] 下部のまとめは、本文を繰り返さず、そのページの帰結を一文で示す。
- [ ] 質問ページと回答ページを使う場合、質問だけで論点が特定できる。
- [ ] 回答ページは質問へ直接答え、別の話題へ移動していない。

## 3. 用語

- [ ] 構成要素名には正式名称を使用している。
  - Goal: 目標と受入条件
  - Skill: 限定責務
  - Workflow protocol: 作業進行規約
  - Knowledge: 組織固有知識
  - Semantic routing: 意味による次作業選択
  - Evidence: 証跡
  - Human acceptance: 人間による受入れ
  - Handoff: 引継ぎ
- [ ] 「実行管理枠」「責務定義」「判断材料」などを、正式名称と同じ階層の要素として並べていない。
- [ ] 初出時に英語名と日本語説明を対応させ、その後の呼称が揺れていない。
- [ ] XRefKit全体を「AI組織」や「AIチーム」と呼んでいない。

## 4. 文章

- [ ] 見出しは結論先行で、名詞の長い連結を避けている。
- [ ] 一文を短くし、一つの文に複数の論点を詰め込んでいない。
- [ ] 「なぜ」「何を」「いつ」「どこに」を曖昧にしていない。
- [ ] `必要がある`、`しなければならない`、`である`を連続使用していない。
- [ ] 誇張、宣伝文句、根拠のない絶対表現を使用していない。
- [ ] 英語を読めない対象者向けの日本語資料では、英語だけで意味を持たせていない。
- [ ] 英語名を使う場合、日本語説明を同じページ内で確認できる。

## 5. 責任境界

- [ ] Tool / Runtimeを、業務判断を代行するAIとして説明していない。
- [ ] Tool / Runtimeの責務を、形式検証、記録、参照解決、進行確認、終了条件確認として表現している。
- [ ] AIの責務を、分析、生成、推論、選択肢、未知事項の表明として表現している。
- [ ] Humanの責務を、受入れ、例外承認、リスク判断、不可逆判断、責任の引受けとして表現している。
- [ ] Evidenceを自動改善の主体ではなく、人間の改善判断への入力として扱っている。
- [ ] 検証通過とHuman acceptanceを同じ判断として扱っていない。

## 6. 視覚

- [ ] 1600×900の固定キャンバスで再現できる。
- [ ] 背景は白または薄い青みのある灰色を基調としている。
- [ ] 本文カードは白、枠線は薄い灰青、主アクセントは青を基本としている。
- [ ] 警告・危険・安定など意味が必要な場合だけ橙、赤、緑を追加している。
- [ ] 一枚で使用するアクセント色は原則2系統以内である。
- [ ] 色だけで問い、答え、状態、重要度を区別していない。
- [ ] 角丸、枠線、余白、見出し位置が同一資料内で一定である。
- [ ] 装飾目的の図形、影、グラデーションを増やしていない。

## 7. 文字と収まり

- [ ] タイトルは通常52〜60pxを基準とし、一行想定のタイトルを折り返していない。
- [ ] 本文は20〜24px以上を基準としている。
- [ ] カード見出しは26〜32pxを基準としている。
- [ ] 文字を収めるためだけに極端に縮小していない。
- [ ] 長い文章はフォント縮小ではなく、短文化またはページ分割で解決している。
- [ ] 文字、カード、フッター、ブランド表示が重なっていない。
- [ ] 最長の日本語・英語表記でもコンテナからはみ出していない。

## 8. 公開ページ

- [ ] 資料タイトル、答える問い、短い概要を表示している。
- [ ] 前の資料、次の資料、全体像、全資料カタログへのリンクがある。
- [ ] 対応言語版が存在する場合、言語切替がある。
- [ ] 画像には内容を表す代替テキストがある。
- [ ] 前後移動をキーボードで操作できる。
- [ ] 既存公開URLを変更していない。

## 9. 生成と検証

- [ ] `render.mjs`と`diagram.css`を正本として変更している。
- [ ] 生成HTMLだけ、またはPNGだけを直接修正していない。
- [ ] HTMLを生成後、すべてのPNGを再生成している。
- [ ] 生成元と`site/`公開物の内容が一致している。
- [ ] `git diff --check`が成功する。
- [ ] サイトビルドと内部リンク検査が成功する。
- [ ] デスクトップと390px前後のモバイル幅で横方向にはみ出さない。
- [ ] 代表ページだけでなく、長いタイトルと長い本文を持つページも目視確認している。

## Review Verdict

- `pass`: 必須項目を満たし、生成・表示検証が完了している。
- `needs_confirmation`: 内容判断または正式用語の選択に人間の確認が必要である。
- `not_applicable`: 資料形式上、対象項目が存在しない。理由を記録する。
- `blocked`: リンク切れ、生成失敗、文字切れ、責任境界の誤説明、未実装機能の記載が残る。
