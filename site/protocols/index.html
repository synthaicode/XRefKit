Common protocols for AI work

The shared contracts cover work progression, reporting, quality review, uncertainty, references, and continuation. Each has its own applicability conditions. Individual Skills define their particular work methods and outputs while using these common controls.

Reporting that supports the next decision

Apply it when a decision framework exists. Agreed evaluation criteria, completion conditions, or a review gate establish that framework. Ordinary conversation uses ordinary prose; loading the reporting contract does not create criteria or a mandatory report.

Lead with the result and a reader perspective. Make the conclusion, material uncertainty or blocker, evidence, and required next action easy to find. Briefly explain which relationship or distinction matters for the user's next judgment. Use an evidence-supported priority only when one is established.

Keep the basis and limits visible. Show what changed, what was checked, what remains unverified, and where the supporting detail can be inspected. Keep workflow status distinct from a domain verdict. Link checklist results to their findings or coverage notes, and state reasons and next owners for unresolved items.

Let the task own the format. The user's requested format takes precedence; otherwise the active task and Skill define the headings, order, detail, and artifact. Use the requested language while preserving exact identifiers. Explicitly enrolled fixed-format outputs use their selected Knowledge quality profile and accepted examples. A human-facing report links to the artifacts or run log and does not replace them.

Workflow progression

The workflow protocol gives a Skill-backed or instruction-backed run a shared progression record. The AI performs the actual work, deterministic tools check the record, and quality review and human acceptance remain separate.

1. Start with a bounded goal

Record the purpose, scope, constraints, responsibility, and completion conditions. Select the applicable Skill or start an instruction-backed run. The runtime opens a run record and assigns execution, checking, quality-review, and handoff roles.

2. Plan observable work

Break the work into concrete items with completion criteria. Identify the expected outputs, evidence, and checks so that progress and completion can be inspected.

3. Execute and preserve evidence

The AI follows the selected method, loads the needed Knowledge, and records outputs, evidence, status, concerns, and judgments. Unknowns, risks, and decisions outside the assigned boundary stay explicit and are resolved or escalated to the appropriate human owner.

4. Verify the workflow record

A deterministic tool checks work-item completion, artifact linkage, concern handling, role separation, and recorded progression. If required records or concern handling are incomplete, verification fails. Repair the records and resolve or escalate the concerns before checking again. The checker does not open output contents or judge their correctness.

5. Review output quality when required

An independent quality reviewer evaluates the actual output against the applicable criteria and records acceptance or a need for repair. This quality judgment is separate from the deterministic record check; the executor does not approve its own quality.

6. Prepare handoff and apply closure

Record the result, evidence, unresolved items, and next responsibility for handoff. The closure gate checks whether the run can close or must remain blocked or escalated. After closure, control returns to the human, who decides acceptance and the next request.

Three separate decisions: verification and closure check procedural completeness; quality review assesses output acceptability; human acceptance determines whether the result is adopted. Passing the workflow gates alone does not prove that the business goal has been accepted.
